## Existing 2.1.8 (source verified)
- DeepSeek model selector for two hardcoded IDs, adaptive/fast/smart/max request policy, optional Pro→Flash fallback, retry and timeout; stream:false; proxy fallbacks specific to Ghostgram. Do not assume IDs still available. Current native broker supports model catalog and SSE but GoldAPI.ai.complete accepts only model/prompt/text/maxTokens/temperature and fixed timeout; thinking/effort and usage extensions need typed additive contract or supported existing GGAPI transport with explicit gates.
- Eight built-in profiles + three custom slots, per-chat profile key, tone/length/emoji/context; short memory up to six 300-character entries, may record generated answer before actual send. Visible/history fallback uses bounded recent snapshots, 16 context/36 summary target, not full historical retrieval.
- Draft/button commands, context reply/translation/manipulation/scam/explanation/profile/clear draft, rewrite, tone, variants (three in one text), summary + three custom prompts. Broadcast channel native sheet response. Export/import settings without key (version label stale 2.1.7); fixed settings list, old proxy/spoiler/header/typing compatibility issues. Current Worker is disposable, JS busy flag not durable; await registered async handler. Existing automatic clear of recognized output should become explicit undo/clear; native cancellation and scope validation are authoritative.

## Proposed 3.0 feature scope
1. Preserve fast AI tap from draft or selected permitted message; optional expanded command panel with model/profile/source and tools; quick action without requiring panel every time. Keep old commands and original tools. Native panel and long-press/menu are proposed reusable UI extensions, not available as complete current API. No typing presence, automatic send, invisible draft or read-state change. Channels without composer show local result. Keep user-confirmed draft preview/insert/manual send, explicit copy, no overwriting changed draft.
2. Dynamic DeepSeek catalog (native modelSource/cache); retain selected valid model, no silent fallback, show provider/model/route/status, distinguish first content time from total elapsed, bounded retry only when safe and consented; native Stop/SSE/partial explicit handling. Optional per-tool model/depth and limits; use native key field, no plaintext key, no proxy unsupported controls. Extend GoldAPI.ai options/usage/timeout and structured result only as needed, backward compatible, validate actual provider capabilities; no guaranteed token cost without reliable pricing/usage. Existing DeepSeek only; additional providers later separate consent and broker allowlists.
3. Grouped settings; custom tool builder with name, command, prompt, output, model/depth, source, menu visibility; bounded registry, duplicate handling and versioned import/export. Profiles library beyond three slots, per-chat overrides and quick selector, tone/length/emoji/system prompt, manually specified context. Constrain registry to existing settings/storage/files quotas, no arbitrary native code. Structured results: three separate answer candidates, explicit select/preview/insert/copy; repeat/refine/shorten on user action. Do not make analysis claim verified truth, especially manipulation/scam/tone; distinguish cues and uncertainty. Custom tools never auto execute instructions from chat/doc text.
4. Context/memory: explicit source draft/selected/eligible bounded snapshot/current-peer confirmed query results/user-provided notes. Preview context categories/count/text as appropriate before external transfer; show limits/truncation; no unlimited history/archive or cross-chat capture. Opt-in manual memory facts/notes, per account/chat/thread when scope supported; view/edit/delete, bounded entries and total quota, no unsent drafts represented as actual messages, no protected/ephemeral content persistence. Existing v2 memory treated as generated/suggested, not silently promoted to facts. Context identity verified in native layer, never caller arbitrary peer IDs.
5. Existing GoldAPI services: user-selected PDF/DOCX/TXT/JSON local extract/analysis, explicit separate DeepSeek approval; system speech for selected text/answer, native Stop. Speech synthesis not audio transcription. Voice/video transcription separate future plugin/service requiring explicit selected eligible media, provider/data consent, limits and actual supported API; no claim DeepSeek text endpoint transcribes audio. Favorites/contacts optional only when requested/authorized; not bulk import or automatic enrichment. Avoid broadening old TTL/protection exceptions.
6. Diagnostics: existing sanitized bounded session journal; show model/status/elapsed/usage when valid without raw content or secret; no exact RAM/CPU metrics. Settings backup schema version and allowlist, validate all before applying, omit credentials, chat memory/IDs and private text by default; explicit update, preserve UUID/Keychain/settings/storage/files, rollback code only. Original exact manifest name includes version: existing update requires matching name/author; choose explicit migration path only after inspection and user approval (keep identity or validated narrow migration/legacy import, no bypass of arbitrary identity validation). Fresh JS init each run; use await, scope revalidation, no cross-context results. Test quota and rollback compatibility.
